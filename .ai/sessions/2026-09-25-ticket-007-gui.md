# 2026-09-25: TICKET-007 `gui` command

**Ask:** build TICKET-007 (a WPF window over the existing scans) on a branch and open a PR.

## What changed

- `lib/Gui.xaml`: the layout. It is plain XAML with no code and no event hooks. Colours are
  `DynamicResource` brushes.
- `lib/Gui.ps1`: the pure helpers (`Get-SusScanOption`, `ConvertTo-SusGridRow`, `Test-SusRowFilter`,
  `Add-SusAllowlistEntry`, `Get-SusDetailLine`, `Get-SusGuiPalette`) and `Show-SusGui`.
  The runspace script only calls exported functions (a test checks this).
- `lib/Report.ps1`: `Get-AttackUrl` moved out of the HTML report, so the GUI and the report
  build the same links.
- `sus-hunt.ps1 gui` relaunches under `-STA` when it needs to. `tools/SusHunt.cmd` is the
  double-click launcher.

## Gotchas

- `New-Object SolidColorBrush (ColorConverter...)` put a Color into the resource, and WPF refused it
  as a Foreground. Use `BrushConverter.ConvertFromString`.
- `.GetNewClosure()` binds a scriptblock to a new dynamic module, so module-private functions
  disappear from it. The filter predicate reads a `$state` hashtable instead.
- `PowerShell.Stop()` waits for the next pipeline step. The C# file walk has none for many seconds,
  so Cancel detaches the runspace and the DispatcherTimer disposes it later.
- `@($list)` on a `List[object]` held in a hashtable throws "Argument types do not match" in
  5.1, even when the list is empty. Use `.ToArray()`. It fired on every timer tick once a scan
  had run. UI Automation did not notice, because the errors only went to the console. The owner
  saw them. Capture stderr when smoke-testing.
- To smoke-test without clicking, drive the window with `System.Windows.Automation`: find elements by
  `x:Name` (AutomationId), then use Invoke, SelectionItem and Value patterns.

## Follow-up: scan runner out of the timer

Lint only reads the code, and the old tests only covered pure helpers, so the `@()` bug reached
the owner. The scan bookkeeping is now in plain functions: `New-SusScanRunner`, `Start-SusScan`,
`Update-SusScan` (one timer tick), `Stop-SusScan` and `Close-SusScanJob`. The WPF timer only moves
their results onto controls. Eight Pester tests drive real runspaces with tiny scripts: output,
arguments, progress, the one-scan lock, cancel then rerun, throw, and a non-fatal error.
Putting the `@()` bug back made 7 of them fail.
